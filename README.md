# Skyping Weather — MVP

**Skyping Weather** is an agricultural intelligence platform that helps farmers and agronomists monitor the health of their land zones in near-real-time. Users draw polygons on an interactive map, and the platform delivers a consolidated risk score alongside the key drivers behind it: vegetation health (NDVI), soil moisture, precipitation, temperature, and wind.

The MVP is intentionally minimal: all environmental data is generated by a deterministic mock layer so the full pipeline runs without any external API keys. Every mock function has the exact same signature as its real-data counterpart, so swapping in Sentinel-2, SMAP, or ERA5 is a one-file change with zero frontend impact.

## Pipeline overview

```
User draws polygon on map
        │
        ▼
Backend computes centroid → passes (lat, lon) to data layer
        │
        ├─ generate_ndvi()           → vegetation index (0–1)
        ├─ generate_soil_moisture()  → volumetric water content (%)
        ├─ generate_precip_7d()      → 7-day precipitation (mm)
        ├─ generate_temperature()    → current temperature (°C)
        └─ generate_wind()           → wind speed (km/h)
        │
        ▼
Risk engine aggregates indices → composite score (0–100) + top drivers + recommendation
        │
        ▼
Frontend renders map layer, metrics cards, 30-day trend chart, and risk panel
```

## Stack
- **Backend:** FastAPI 0.115, Pydantic v2, Shapely (geometry), open CORS, basic observability (`X-Response-Time-ms` middleware).
- **Frontend:** React 18 + Vite 5, Leaflet + leaflet-draw (map and polygon drawing), Recharts (trend charts), dark-theme CSS.
- **Data layer:** Deterministic mock by centroid (same input → same series). Interfaces ready for Sentinel Hub / Copernicus / SMAP / ERA5 / Open-Meteo.

## Run locally

### Option A — Docker (recommended)
```bash
cd skyping-weather
docker compose up --build
```
- Backend: http://localhost:8000 (interactive docs at `/docs`)
- Frontend: http://localhost:5173

### Option B — Without Docker
**Backend:**
```bash
cd skyping-weather/backend
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

**Frontend:**
```bash
cd skyping-weather/frontend
npm install
npm run dev
```

## API endpoints
| Method | Path | Description |
|---|---|---|
| GET    | `/health` | Liveness check |
| GET    | `/api/v1/zones` | List tenant zones |
| POST   | `/api/v1/zones` | Create zone `{name, geometry}` |
| GET    | `/api/v1/zones/{id}` | Zone detail |
| DELETE | `/api/v1/zones/{id}` | Delete zone |
| GET    | `/api/v1/indices/{zone_id}` | NDVI + moisture + weather + trends |
| GET    | `/api/v1/indices/point/preview?lat&lon` | Point preview without saving |
| GET    | `/api/v1/risk/{zone_id}` | Risk score + drivers + recommendation |
| GET    | `/api/v1/summary` | Full dashboard payload in one request |

All endpoints accept an `X-Tenant-Id` header for simple multi-tenant isolation from day one.

## Replacing mocks with real data
`backend/app/mock_data.py` exposes five functions (`generate_ndvi`, `generate_soil_moisture`, `generate_precip_7d`, `generate_temperature`, `generate_wind`) plus `generate_trend`. Each accepts `(lat, lon)` and returns the same type that the real source would return. Integration paths:

- **NDVI:** Sentinel-2 L2A via Sentinel Hub Statistical API or Copernicus Data Space (SCL-filtered mean B8/B4).
- **Soil moisture:** SMAP L3 (9 km) or ESA CCI-SM monthly composite.
- **Weather:** Open-Meteo (free, no key) or ERA5-Land via CDS.

No frontend signature changes required.

## Multi-tenancy
The `X-Tenant-Id` header isolates data in memory. Migration to persistent storage = a `zones(tenant_id, ...)` table in Postgres/PostGIS with row-level security.
